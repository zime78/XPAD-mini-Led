YouTube LCD 처리 워크플로

공식 watch 페이지를 숨은 Chromium 창에서 재생한다. 디코드와 스피커는 렌더러에 남고, 같은 로그인 세션의 소리 창은 재생만 하고, 음소거 LCD 창에서 HID 전송×0.55마다 RGB565를 뽑아 기기에는 최신 1장만 보낸다. 미리보기 베젤은 그 전송 간격을 보여 준다.

Codec / decoder

앱은 디코더를 직접 안 연다

  • 숨은 창이 youtube.com/watch?v=…&vq=tiny 를 연다.
  • YouTube MSE가 보통 WebM/MP4 + Opus/AAC를 넣는다.
  • 디코드는 Chromium media stack. 로그의 hwdecode=on은 라벨일 뿐, VideoToolbox API 호출은 코드에 없다.
  • macOS에서 Chromium 기본값은 VideoToolbox HW 디코드. 실패 시 SW로 떨어진다.
  • 화질 고정(tiny)은 음소거 LCD 창만 한다. 소리 창은 건드리지 않는다.

Computer / CPU

픽셀만 메인에서 다시 만든다

  • 오디오는 소리 창 AudioService → CoreAudio. LCD 창은 음소거다.
  • LCD 창만 HID drawMs×0.55(40–100ms)마다 getImageData로 240×135를 뽑는다.
  • 메인에서 RGB565-LE (64800B). 미리보기는 그 버퍼를 PNG로 복원한다. 베젤은 전송 간격.
  • 워커가 0x25 최신 1장만 전송. 유휴 시 220ms 재전송. 전송 후 lcdStats.
  • 위치가 1.5초 이상 벌어지면 LCD 창만 소리 창에 맞춘다.

Verify now

동작 확인

  • 콘솔 source=split-audio-lcd 이면 두 창 분리.
  • lcd quality=tiny — LCD 창 화질 고정.
  • capture=auto · hidIgnorePct≈45 — HID보다 조금 빨리 뽑아 한 장 겹침.
  • 베젤 NNms는 전송 간격(hidDrawMs). 끝-끝 딜레이가 아니다.
  • 앱 미리보기와 실기기 장이 같이 끊기면 정상(같은 RGB565).
  • 광고 타이밍이 창마다 달라도 허용.
